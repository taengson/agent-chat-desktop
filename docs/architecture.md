# Agent Chat Desktop 아키텍처

## 1. 문서 목적

이 문서는 Agent Chat Desktop의 구현 기준을 정의합니다. 프로젝트가 성장하더라도 채팅 기능, AI Provider 및 로컬 저장소가 서로 강하게 결합되지 않도록 책임과 경계를 명확히 하는 것이 목적입니다.

현재 확정되지 않은 선택은 **제안**으로 표시합니다. 제안은 구현 전에 검증하고 결정되면 이 문서와 진행 현황 문서에 반영합니다.

## 2. 시스템 목표

1. vLLM을 포함한 OpenAI 호환 API와 스트리밍 방식으로 대화한다.
2. 사용자가 여러 서버와 모델을 연결 프로필로 관리한다.
3. UI와 특정 AI 서비스의 API 형식을 분리한다.
4. 대화와 설정을 로컬에서 관리하고 인증 정보를 안전하게 취급한다.

## 3. 범위

### 초기 범위

- 단일 사용자용 데스크톱 애플리케이션
- OpenAI 호환 모델 목록 조회
- 텍스트·코드·텍스트 기반 PDF·`.docx`·`.xlsx` 첨부를 포함한 스트리밍 채팅
- 생성 중단과 오류 처리
- Markdown 파일 기반 대화 기록의 로컬 저장

### 후속 범위

- 프레젠테이션·레거시 Office 문서·이미지를 포함한 멀티모달 메시지
- 도구 호출과 구조화된 응답
- 여러 AI Provider 어댑터

### 현재 범위에서 제외

- 중앙 사용자 계정과 클라우드 동기화
- 팀 단위 권한 관리
- 자체 모델 추론 서버 구현
- 자체 에이전트 런타임 구현

## 5. 컴포넌트 책임

### Frontend

- 대화 및 메시지 목록 표시
- 연결 프로필과 모델 선택
- 일반 채팅과 벤치마크의 추론 강도 선택 및 고강도 설정 경고 표시
- 사용자 입력, 텍스트·코드·텍스트 기반 PDF·`.docx`·`.xlsx` 첨부와 생성 중단 요청
- 스트리밍 델타를 수신해 응답 갱신
- AI 응답을 GFM Markdown으로 안전하게 렌더링
- 완료된 벤치마크 결과 창과 기록 분석·비교·실무·개발 비교 화면에서 Markdown·HTML 보고서 내보내기 제공. 기본 파일명에는 모델·질문지를 사용하고, 비교는 A 모델과 나머지 기록 수를 사용해 짧게 구성
- 결과 동기화 화면에서 v2 장치 신원 fingerprint, 앱 내 직접 TLS 수신 설정·시작·중지와 로컬 보안 활동 기록 제공
- 오류, 재연결 및 작업 상태 표시

프런트엔드는 vLLM이나 특정 Provider의 HTTP 스키마를 직접 다루지 않습니다.

### Wails API

- 프런트엔드가 호출할 명령 제공
- Go 도메인 타입에서 생성된 프런트엔드 타입 제공
- 스트리밍 및 작업 상태 이벤트 전달
- 스트리밍 완료 시점의 토큰 사용량 전달
- v2 장치 신원·공개 설정·감사 기록 조회와 변경 명령, TLS 개인키·CSR 생성 명령을 제공. 이후 E2EE·동기화 명령을 같은 v2 API에 추가
- 애플리케이션 시작과 종료 수명 주기 관리

공개 메서드는 작게 유지하고 실제 로직을 서비스 계층에 위임합니다.

### Chat Service

- 사용자 메시지를 대화에 추가
- 선택된 연결 프로필과 Provider 결정
- 스트리밍 요청 시작과 취소
- 수신 이벤트를 공통 채팅 이벤트로 변환
- 첫 출력과 출력 유휴 시간을 감시해 멈춘 요청만 취소
- 완료 또는 실패한 응답을 대화 기록에 반영

### Provider Layer

- 모델 목록 조회
- 채팅 요청 전송
- 선택한 추론 강도를 OpenAI 호환 `reasoning_effort`로 변환하고 자동 모드에서는 필드를 생략
- 스트리밍 응답 파싱
- 서비스 오류를 공통 오류로 변환
- Provider별 인증과 옵션 처리
- Provider가 제공하는 토큰 사용량을 공통 형식으로 변환

vLLM은 별도 도메인 구현이 아니라 OpenAI 호환 Provider의 연결 대상 중 하나로 취급합니다.

### Storage Layer

- 대화·메시지와 첨부한 텍스트·코드·PDF·`.docx`·`.xlsx`에서 선택한 추출 내용을 사용자 설정 폴더의 Markdown 파일로 저장
- 대화 목록용 제목과 요약 메타데이터를 Markdown 파일에서 조회
- 모델 벤치마크의 추론 강도·테스트 항목·응답·성능 수치를 별도 Markdown 파일로 저장하고, Markdown·HTML 보고서 안에 복원용 원본 데이터를 포함해 다른 환경의 결과를 가져올 수 있도록 함. 기록 비교는 문서·한국어 실무 또는 개발·지시 이행 질문지를 먼저 선택해 해당 기록만 A·B·C 선택 목록에 표시하며, 목록 항목은 모델·추론 강도·연결 프로필·실행 시각을 함께 표시함. 추론 강도 정보가 없는 기존 기록은 자동 모드로 취급함. 실무·개발 비교는 같은 모델·서버·추론 강도의 문서·한국어 실무 기록과 개발·지시 이행 기록을 자동으로 한 조건으로 묶어, A·B·C에서 조건 하나씩만 선택하면 두 질문지의 4문항씩 총 8개 그래프로 같은 지표를 비교하고 현재 조건 전체를 보고서로 내보낼 수 있음. 조건 사이의 테스트 구성과 추론 강도가 일치하는지 경고로 안내함. 왼쪽 사이드바의 내·가져온·동기화된 벤치마크 목록은 독립적으로 접고 펼칠 수 있고, 이 화면 상태는 웹뷰 로컬 저장소에 보존함. 보고서 기본 파일명은 단일 기록일 때 `benchmark_[모델]__[추론 강도]__[질문지]`, 두·세 기록 비교일 때 `benchmark_[A 모델]_vs_1other|2others__[추론 강도]__[질문지]`, 실무·개발 비교일 때 `benchmark_[A 모델]_vs_1other|2others__[추론 강도]__문서-개발`이며 서로 다른 추론 강도를 비교하면 `r-mixed`를 사용함. 파일 시스템에서 허용하지 않는 문자는 공백으로 정리하고, 가져올 때는 저장된 결과와 ID·가져온 상태를 제외한 내용의 지문을 비교해 같은 결과를 제외함
- v2 공개 설정과 감사 기록은 사용자 설정 폴더의 `benchmark-sync-v2.json`에 소유자 전용 권한으로 저장함. 장치의 Ed25519 서명 개인키와 X25519 키 합의 개인키는 운영체제 비밀 저장소에만 보관하며, 파일과 UI에는 공개키 fingerprint·키 ID만 둠. TLS 인증서·개인키는 사용자가 지정한 PEM 파일에서 앱이 직접 읽고, 설정 파일에는 경로만 둠. 완료된 로컬 결과에는 원본 장치 ID·공개키·digest·서명을 포함한 proof를 보존함. 이후 v2 전송은 이 proof를 검증한 결과만 `sync` 출처로 병합하고, 동일 결과는 `local > report > sync` 우선순위를 유지함
- 마지막으로 사용한 LLM 서버 URL을 별도 Markdown 파일에 저장
- 애플리케이션 설정 저장
- 향후 저장 형식 변경을 위한 마이그레이션 관리

AI Provider API 키는 일반 데이터베이스 또는 JSON 설정에 평문으로 저장하지 않습니다. v2 장치 개인키, 향후 초대 secret 및 E2EE 세션 비밀값은 일반 설정 파일에 저장하거나 프런트엔드·동기화 데이터에 포함하지 않습니다.

## 7. 핵심 도메인 모델

```go
type ConnectionProfile struct {
    ID           string
    Name         string
    ProviderType string
    BaseURL      string
    Model        string
    SecretRef    string
}

type Message struct {
    ID             string
    ConversationID string
    Role           string
    Parts          []MessagePart
    Status         string
    CreatedAt      time.Time
}

type MessagePart struct {
    Type     string
    Text     string
    MIMEType string
    URI      string
}
```

`MessagePart`를 사용해 텍스트로 시작하되 이후 이미지, 파일과 도구 호출로 확장할 수 있게 합니다. 실제 필드와 타입은 첫 구현에서 Go 타입으로 검증한 뒤 확정합니다.

## 8. Provider 인터페이스

Provider는 외부 AI 서비스의 차이를 애플리케이션에서 숨깁니다.

```go
type Provider interface {
    ListModels(ctx context.Context, profile ConnectionProfile) ([]Model, error)
    StreamChat(ctx context.Context, request ChatRequest) (<-chan ChatEvent, error)
}
```

공통 `ChatEvent`는 최소한 다음 상태를 표현합니다.

- `started`: 요청이 시작됨
- `delta`: 응답 일부를 수신함
- `completed`: 정상 완료됨
- `failed`: 오류로 종료됨
- `cancelled`: 사용자 요청으로 취소됨

`usage`는 선택적 보조 이벤트로, Provider가 최종 스트림 청크에 포함한 입력·출력·합계 토큰을 전달합니다. `metrics`는 앱이 측정한 총 응답 시간과 첫 토큰 도착 시간을 전달합니다. 사용량을 제공하지 않는 호환 서버도 채팅 완료 자체는 정상 처리합니다.

채널 종료만으로 완료와 실패를 구분하지 않고 명시적인 종료 이벤트를 전달합니다.

## 9. 채팅 요청 흐름

```text
사용자 전송
  → Frontend가 첨부 문서를 제목·시트·문단 단위로 나누고 질문 관련 단위와 문맥을 선택
  → 사이드바의 이전 대화 포함 설정에 따라 현재 질문만 또는 이전 대화도 요청에 포함
  → 자동 이외의 추론 강도를 reasoning_effort에 포함
  → Frontend가 SendMessage 호출
  → Chat Service가 사용자 메시지 저장
  → Provider가 HTTP 요청 시작
  → Go가 스트리밍 응답 파싱
  → Wails 이벤트로 delta 전달
  → 최종 usage 이벤트로 토큰 사용량 전달
  → 완료 이벤트로 응답 시간 전달
  → Frontend가 응답 메시지 갱신
  → 완료 상태와 최종 메시지 저장
```

각 생성 요청은 고유한 ID와 `context.CancelFunc`를 갖습니다. 사용자가 중단하면 요청 ID에 대응하는 컨텍스트를 취소하고, 부분 응답은 `cancelled` 상태로 보존합니다. 일반 채팅은 첫 출력까지 15분을 기다리고, 첫 출력 뒤에는 델타가 도착할 때마다 유휴 타이머를 갱신합니다. 따라서 출력이 계속되는 한 전체 실행 시간 제한은 없으며, 출력이 5분간 멈춘 요청만 실패로 종료합니다. 모델 실험실은 비교 가능한 실행을 위해 각각 10분과 60초를 사용합니다.

채팅 사이드바의 `이전 대화 포함`은 앱 시작 시 꺼져 있습니다. 새 질문과 다시 생성은 공통 요청 구성 함수를 사용해, 꺼져 있으면 대상 질문과 첨부 텍스트만 전송하고 켜져 있으면 같은 대화의 이전 질문·답변·첨부 텍스트를 포함합니다. 화면과 저장소의 대화 기록은 이 설정과 관계없이 유지합니다. 벤치마크 요청은 각 테스트 질문을 독립적으로 전송합니다.

채팅 입력창의 추론 강도 선택 옆에 현재 모델의 누적 입력·출력·전체 토큰을 표시합니다. 서버가 제공한 사용량을 합산하며, 모델 변경·모델 목록 새로고침·서버 주소 변경·앱 재시작 시 초기화됩니다. 누적 사용량은 컨텍스트 잔여량을 나타내지 않습니다. 사이드바는 오른쪽 위 `‹` 버튼으로 숨기고, 접힌 상태에서 화면 왼쪽 위 `›` 버튼으로 다시 열 수 있으며 표시 상태는 저장하지 않습니다.

## 10. 오류 처리

UI에는 내부 오류 문자열을 그대로 전달하지 않고 다음과 같은 공통 오류 코드와 사용자용 메시지를 전달합니다.

- 잘못된 서버 URL
- 연결 실패 또는 시간 초과
- 인증 실패
- 모델을 찾을 수 없음
- 요청 제한
- 잘못된 API 응답
- 스트리밍 중 연결 종료
- 첫 출력 대기 또는 출력 유휴 시간 초과
- 사용자 취소

진단에 필요한 기술 정보는 민감한 헤더와 API 키를 제거한 뒤 로그에 기록합니다.

## 11. 저장소와 보안

- 대화와 메시지는 사용자 설정 폴더의 대화별 Markdown 파일로 저장합니다. 파일의 frontmatter에는 ID와 생성·수정 시각을 두고, 본문에는 사람이 읽을 수 있는 메시지를 기록합니다.
- 앱 시작 시 대화 목록을 표시하고 사용자가 선택한 대화만 채팅 화면에 적용합니다. 새 대화 생성은 별도의 목록 UI 동작으로 제공합니다.
- 사용자가 활성 대화의 삭제를 확인하면 해당 대화 Markdown 파일 하나만 삭제합니다. 마지막으로 열었던 대화의 자동 복원은 현재 제공하지 않습니다.
- 마지막 LLM 서버 URL은 `profiles/last-used.md`에 저장하고 앱 시작 시 복원합니다. 재사용할 연결은 `profiles/{id}.md`에 이름과 서버 URL만 저장해 추가·선택·전환·삭제할 수 있습니다. 모델은 서버에서 다시 조회하므로 저장하지 않습니다.
- 모델 벤치마크는 저장된 연결 프로필 하나와 모델 하나를 사용합니다. 사용자가 선택한 추론 강도를 모든 테스트에 동일하게 적용하고 기록·분석·비교·내보내기 보고서에 함께 보존합니다. 지시 이행·추론·코드·한국어 설명의 기본 프롬프트는 실행 전에 사용자가 수정할 수 있으며, 테스트는 서버 부하가 서로 영향을 주지 않도록 순차로 생성합니다. 테스트 질문·응답·응답 시간·첫 토큰 시간·토큰 사용량은 `model-benchmarks/{id}.md`에 저장합니다. 결과는 현재 실행 환경의 측정 기록이며 범용 모델 순위를 의미하지 않습니다.
- `main`의 벤치마크 동기화는 v2 전용으로 다시 구성한다. v1 LAN HTTP·일회용 코드·Bearer 토큰 코드와 UI는 `main`에 두지 않고 태그 `benchmark-sync-v1`에 보관한다. v2 화면을 처음 열면 OS 비밀 저장소에 Ed25519/X25519 장치 키를 한 번 만들고 공개 fingerprint를 표시한다. 사용자는 raw IP·localhost를 제외한 외부 HTTPS 도메인, 일치하는 인증서 PEM·개인키 PEM, 수신 주소를 설정할 수 있다. 필요한 경우 앱에서 새 TLS 개인키와 CSR 파일을 만든 뒤 CA가 발급한 인증서를 파일 선택 창에서 고를 수 있다. 앱은 TLS 1.3 listener를 직접 열고 앱 시작 시 다시 열며, 256비트 초대 secret과 장치 서명으로 페어링 요청·응답을 보호한다. 양쪽 사용자가 fingerprint를 확인·승인한 공개키만 신뢰 장치로 저장한다. 장치 이름·공개 주소·PEM 경로·민감정보를 제외한 감사 로그만 `benchmark-sync-v2.json`에 저장한다. E2EE 세션과 실제 전송은 다음 단계다.
- v2 전송은 원본 장치 ID·원본 벤치마크 ID·결과 지문과 원본 proof를 사용한다. proof의 공개키·digest·서명이 모두 맞는 결과만 병합하며, 같은 지문은 `내 PC > 보고서 > 동기화` 순서를 유지한다. 외부 기록을 로컬에서 삭제하면 그 지문을 제외 목록에 보관해 다시 가져오지 않으며, 삭제 자체는 다른 PC로 전파하지 않는다. 감사 로그는 이 PC에만 최근 200건을 보관하고 사용자가 비울 수 있다.
- 첨부 원본 파일은 저장하거나 모델에 직접 전송하지 않습니다. 텍스트 기반 PDF, `.docx`, `.xlsx`에서 읽은 텍스트를 제목·시트·문단 단위로 나눈 뒤 질문 관련성과 앞뒤 문맥을 기준으로 선택합니다. 관련 단위를 찾지 못하면 앞·뒤 발췌본을 사용합니다. 현재 스캔 PDF OCR과 `.doc`, `.xls`, `.ppt`, `.pptx`는 지원하지 않습니다.
- 첨부 파일은 메시지당 최대 4개, 파일당 5MB, 원본 합계 12MB로 제한합니다. 모델에 보내고 기록하는 선택 텍스트는 파일당 최대 240KB, 메시지 전체 최대 512KB입니다. `.xlsx`는 최대 25만 셀을 읽습니다.
- API 키는 저장·복원하지 않고 앱 실행 중 메모리에서만 사용합니다. URL의 사용자 정보, 쿼리 문자열, 프래그먼트는 API 키나 토큰을 포함할 수 있어 저장하지 않습니다.
- 프런트엔드에는 API 키 원문을 반환하지 않습니다.
- 장치 개인키, E2EE 세션 비밀값, 초대 secret은 프런트엔드·로그·벤치마크 전송 데이터에 포함하지 않습니다. 초대 secret은 v2 페어링이 구현될 때 128비트 이상 난수로 한 번만 발급하고, 확인 뒤 즉시 폐기합니다.
- 로그에 Authorization 헤더, 전체 요청 헤더, 개인키·초대 secret·평문 및 암호문 본문이 기록되지 않게 합니다.
- v2 원격 연결은 유효한 TLS 인증서가 있는 HTTPS만 허용하며, raw IP·원격 평문 HTTP·인증서 검증 우회는 허용하지 않습니다. TLS는 외부 프록시가 아니라 앱 프로세스가 직접 종료합니다.

## 14. 현재 구현 기준선

2026-09-08 기준 로컬 LLM 채팅, 대화 저장, 문서 첨부와 모델 실험실이 동작합니다.

- React UI에서 서버 URL과 선택적 API 키를 입력하고 `/v1/models`의 모델을 선택합니다.
- Go 백엔드의 OpenAI 호환 어댑터가 `/v1/chat/completions`에 스트리밍 요청을 보냅니다.
- SSE 델타는 Wails의 `chat:event` 이벤트로 전달되며 UI가 응답을 실시간으로 갱신합니다.
- 각 요청은 요청 ID와 취소 컨텍스트를 사용합니다. 프런트엔드의 중단 요청은 해당 HTTP 요청으로 전파됩니다. 일반 채팅은 출력이 계속 도착하는 동안 유지하고, 첫 출력 15분·출력 유휴 5분만 감시합니다.
- 텍스트·코드·텍스트 기반 PDF·`.docx`·`.xlsx` 첨부를 로컬에서 텍스트로 추출합니다. 긴 문서는 질문 관련 문서 단위와 앞뒤 문맥을 선택해 전송하며, 원본 파일은 저장하지 않습니다.
- 대화·연결 프로필·모델 실험실 결과는 사용자 설정 폴더의 Markdown 파일로 저장합니다. API 키와 선택 모델은 저장하지 않습니다.
- 메시지 목록은 독립적인 스크롤 영역이며, macOS WebView에서도 동작하도록 휠 입력을 직접 처리하고 이전·최신 메시지 이동 수단을 제공합니다.
- 서버 주소는 루트 경로 또는 `/v1` 경로를 받을 수 있으며 백엔드가 API 엔드포인트를 정규화합니다.
- 모델 조회 및 스트리밍 파서에는 모의 HTTP 응답 기반 테스트가 있습니다.
- 실제 로컬 LLM 서버에서 모델 조회와 스트리밍 대화를 확인했습니다.
